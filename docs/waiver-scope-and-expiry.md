# 웨이버 범위와 만료

웨이버는 결함 수정이나 검증 통과가 아니라, 승인자가 한정된 위험을 받아들인 기록이다. 새 웨이버는
승인 시점에 해당 런의 `design_revision`에 자동으로 묶이고 만료 시각을 가진다. 화면 기본값은 90일이며
API에서 만료를 생략해도 서버가 90일을 적용한다. 명시한 만료는 현재보다 미래이고 365일 이내여야
하며 시간대를 포함해야 한다.

현재 웨이버 응답에는 `design_revision`, `expires_at`, `active`, `inactive_reason`이 포함된다.
만료되거나 저장된 설계 리비전과 런 근거의 리비전이 다르면 상태 기록은 `waived`로 유지되지만 해당
error/critical 위반은 게이트와 전체 위반의 차단 개수에 다시 포함된다. 화면에는 만료 또는 범위 불일치와
재차단 사실을 표시한다. 재승인이 필요하면 기존 웨이버를 재오픈한 뒤 새 범위와 만료로 승인한다.
AI는 웨이버를 승인·연장·재활성화하지 않는다.

기능 도입 전에 만들어진 웨이버는 `expires_at=null`인 기존 무기한 기록으로 유지한다. 과거 승인을
소급 변경하지 않으며 화면과 내보내기에 이 한계를 표시한다. 새 웨이버부터 만료가 필수로 저장된다.

현재 웨이버 범위는 게이트 JSON, 검증된 근거 ZIP, 위반 내보내기와 사람의 사인오프 결정에 포함된다.
웨이버를 해제해도 append-only 위반 이벤트에는 당시 `waiver_design_revision`과
`waiver_expires_at`이 남는다. 원래 위반 상태와 상용 보고서 원본은 바뀌지 않는다.
