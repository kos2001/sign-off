# 사전 분석 API의 입력 검증

IR-drop, 글리치 전력, 타이밍 요약 API는 JSON 숫자만 받습니다. 숫자처럼 보이는 문자열과
불리언은 숫자로 변환하지 않으며 NaN/Infinity/유한 범위를 벗어난 숫자를 거부합니다.
입력이 올바르더라도 연산 결과가 유한한 숫자로 표현되지 않으면 422로 거부합니다.

## 크기와 범위

| 분석 | 지원 입력 |
| --- | --- |
| IR-drop | 1–256행 × 1–256열. 세 행렬은 직사각형이고 같은 크기여야 함 |
| 밀도·스위칭 활동 | 각 값 0–1 |
| PDN 강도 | 각 값 양수 |
| IR scale | 0 이상 |
| 핫스팟 임계 비율 | 0–1 |
| Vdd·클록 주기 | 양수 |
| 글리치 네트 | 1–10,000개, 이름 최대 200자, cap_ff 양수 |
| 토글률 | 0 이상이며 total_toggle_rate ≥ functional_toggle_rate |
| 전파 비율 | transport_fraction 0–1 |
| 타이밍 코너 | 1–64개, 공백 제거 후 고유한 이름 1–160자 |
| 코너별 슬랙 | 1–10,000개, 모든 코너의 개수가 같아야 함 |
| 전체 코너 슬랙 값 | 총합 최대 100,000개 |
| PBA 추정 크레딧 | 0 이상 |

타이밍 입력에 endpoint_ids를 제공하면 같은 ID끼리 대응하며 코너별 순서가 달라도 됩니다.
ID가 없는 경우에는 같은 위치가 같은 종점이라고 가정하며, 응답과 화면에 순서 기준임을 표시합니다.
글리치 입력에서 전체 토글률이 기능 토글률보다 작으면 이전의 0 클램프 대신 입력 오류로
반환합니다. 모순된 원본 데이터를 수정한 뒤 다시 분석하세요.

## 오류 응답과 화면

잘못된 필드·크기·숫자에는 HTTP 422를 반환합니다. Pydantic 입력 검증 오류의 detail에는
loc(필드 위치), msg(이유), type(오류 종류)만 포함하고 원본 입력 배열·소스는 되돌려 보내지 않습니다.
입력 숫자가 유한하지만 계산이 넘치면 `inputs exceed the supported numerical range`를 반환합니다.

프런트엔드는 최대 3개의 필드 오류와 추가 오류 여부를 표시합니다. 예를 들어
`nets.0.cap_ff`는 첫 번째 네트의 cap_ff 필드입니다. 요청 실패 후 입력을 유지합니다.

이 제한은 파싱된 분석 데이터의 지원 크기입니다. API는 별도로 원시 HTTP 본문 전체에 기본
64 MiB 상한을 적용하며 자세한 설정은 [운영 점검](operations.md#http-요청-본문-상한)을 참고하세요.
리버스 프록시 버퍼·시간 제한과 메모리·CPU 격리는 별도로 구성해야 합니다. 서비스 함수를 Python에서
직접 부르는 경우 API 스키마와 전송 본문 검증이 자동 적용되지는 않습니다.

검증: `backend/tests/test_analysis_validation.py`의 경계·비유한 숫자·불일치 데이터·산술 범위 검사와
기존 정상 분석 회귀. `scripts/browser_request_errors_check.mjs`는 422 필드 오류 표시와
입력 유지, 내부 입력 비노출, 모바일 표시를 모의 응답으로 확인합니다.

## 종점 ID 기준 타이밍 병합

각 코너에 `endpoint_ids`를 슬랙과 같은 길이로 제공합니다. 모든 코너가 ID를 제공하거나
모든 코너가 생략해야 합니다. ID는 1–200자의 문자열이며 공백만 있거나 제어 문자를 포함할 수
없습니다. 한 코너 내 ID는 고유해야 하고 모든 코너의 ID 집합이 정확히 같아야 합니다.
대소문자나 앞뒤 공백을 임의로 정규화하지 않습니다. 누락 종점을 0으로 채우지 않습니다.

```json
{
  "corners": [
    {"name": "slow", "endpoint_ids": ["a/D", "b/D"], "endpoint_slacks_ps": [-10, 20]},
    {"name": "fast", "endpoint_ids": ["b/D", "a/D"], "endpoint_slacks_ps": [5, -20]}
  ]
}
```

위 입력은 a/D의 최악 슬랙 -20 ps, b/D의 최악 슬랙 5 ps로 병합합니다. 첫 코너의 ID 순서를
출력 순서로 사용합니다. 종점 ID를 생략한 입력은 기존의 위치 기준 병합으로 처리합니다.
입력 ID가 같다는 것은 실제 설계 리비전·경로·전체 코너 검증의 완료까지 증명하지 않습니다.

응답에 다음 필드를 추가합니다.

- `endpoint_alignment`: `by_id` 또는 `positional`.
- `endpoint_ids`: 첫 코너 순서의 ID 목록, 순서 기준이면 null.
- `merged_slacks_ps`: 전체 병합 슬랙 목록. 입력의 ID 또는 위치 기준 순서를 유지합니다.
- `worst_endpoints`: 최악 순으로 최대 20개. 원래 위치의 0부터 시작하는 index, ID,
  slack_ps, 같은 최악 슬랙을 만든 모든 limiting_corners를 제공합니다.

PBA 크레딧도 같은 병합 결과에만 적용하며 원래 슬랙이나 원본 입력을 수정하지 않습니다.

WNS·TNS는 API에서 소수점 자릿수로 반올림하지 않습니다. 예를 들어 -0.00001 ps도 음수로
유지되어 위반 수와 요약 수치가 일치합니다. TNS는 `math.fsum`으로 음수 슬랙을 합산하여
크기가 다른 항목의 단순 누적에서 생기는 정밀도 손실을 줄입니다. 입력·계산·응답은 여전히
배정밀도 부동소수점 수이며 임의 정밀도 십진 계산을 제공하지 않습니다. 합계가 지원 범위를
넘으면 422로 거부합니다. 같은 규칙은 코너별·병합·PBA 추정 요약에 적용됩니다.
화면의 WNS·TNS 및 최악 종점 목록에도 서버 값을 추가 반올림 없이 표시합니다.

분석 화면의 **MMMC 타이밍 요약 → 분석 데이터 편집**에서 코너 JSON 배열을 수정할 수 있습니다.
편집기는 최대 2,000,000자를 받습니다. 입력이나 크레딧을 바꾸면 이전 결과를 지워 잘못된
입력과 결과가 함께 표시되지 않게 합니다. 차트는 서버가 반환한 슬랙의 앞 50개를 입력 순서로
보여주며, 최악 종점 목록은 최대 20개를 따로 표시합니다. 기본 Ibex 데이터는 설명용 예제입니다.

슬랙 차트는 화면 너비에 맞춰 음수를 왼쪽, 양수를 오른쪽에 표시하고 값을 항상 보여줍니다.
표시된 종점 중 최소 슬랙은 동률을 포함해 강조합니다. 행의 숫자는 유효 숫자 최대 6자리이며,
아주 작거나 큰 값은 유효 숫자 최대 4자리의 지수 표기를 사용합니다. 클릭 또는 Tab으로 이동한 뒤 Enter·Space를 누르면
전체 종점 ID와 서버에서 받은 슬랙 값을 추가 반올림 없이 확인할 수 있습니다.
스크린 리더의 행 이름에도 이 값을 제공합니다.

`backend/tests/test_timing_identity.py`는 뒤섞인 순서, 중복/누락 ID, 동률 코너, PBA와 기존
순서 입력 호환성을 검증합니다. `scripts/browser_timing_identity_check.mjs`는 실제 분석 API에
예제 코너를 보내 편집·병합·차트·오류·모바일 표시를 확인하며 DB 기록을 만들지 않습니다.
320·390·1440px 차트 폭, 키보드 상세 열기/닫기와 이동, 동률 최소값, 긴 ID,
작은 음수·0·큰 수의 표시도 검증합니다.
