# 스테이지 게이트의 검증 근거와 설계 리비전

게이트는 각 필수 도메인의 **해당 스테이지 최신 런**을 사용한다.
생성 시각이 같으면 큰 런 ID를 선택한다. 실패·실행 중인 최신 런을 건너뛰거나
리비전을 맞추기 위해 과거의 통과 런을 선택하지 않는다.

## 도메인 검증 범위

- 수동 입력 또는 이전 데이터의 `passed` 상태만으로 준비 완료를 인정하지 않는다.
- 외부 툴 이름을 입력하거나 위반을 웨이버 처리해도 검증 범위가 증명되지는 않는다.
- RTL은 보관된 ladder 근거에서 필수 단계 통과를 확인한다.
- OpenSTA 및 서명 없는 상용 경로 보고서는 전체 STA 범위를 증명하지 않으므로 게이트를 열지 않는다.
- 서버에 등록된 수집기의 유효한 HMAC 증명이 프로젝트·스테이지·리비전·원본과 전체 STA/DRC/EM·IR
  실행 범위를 결합하고 결과가 통과했을 때만 해당 상용 런을 준비 완료로 인정한다.
- 서명 없는 STA/DRC/EM·IR과 전력, 열, RTL 회귀의 상용 보고서 가져오기는 보고서에 담긴
  범위만 보존한다. 완전한 툴 실행 범위를 증명하지 않으므로 단독으로 게이트를 열지 않는다.

각 도메인의 `ready`, `reason`, `run_id`, `open_blocking_violations`, `evidence_source`에
선택된 런의 `design_revision`을 함께 반환한다. 위반 수와 실제 런 상태는 변경하지 않는다.

## 리비전 검사

`GET /projects/{project_id}/signoff-status?stage=...` 응답의 `revision_check`:

- `status`: `consistent` / `missing` / `mismatch`
- `revisions`: 선택된 런들의 비어 있지 않은 리비전, 중복 제거·정렬
- `missing_domains`: 런 또는 리비전이 없는 필수 도메인
- `common_revision`: 모든 필수 도메인의 리비전이 일치할 때만 값 제공

공백만 있는 값도 누락으로 취급한다. 서로 다른 값이 있으면 `mismatch`이며,
누락 도메인이 동시에 있으면 그 목록도 보존한다. 대소문자를 구분하고 같은 이름으로
임의 통합하지 않는다. `ready`는 모든 도메인 준비 완료와 리비전 일치를 함께 요구한다.

리비전은 사용자가 선언한 식별자다. 이름의 일치는 실제 netlist/제약/라이브러리 입력의
동일성, 원본 툴의 진위 또는 전체 커버리지를 증명하지 않는다. 이런 근거의 수집과
검증은 추가로 필요하며, 리비전 검사만 통과했다고 사인오프를 승인하지 않는다.

프로젝트 화면에 도메인별 선택 런·리비전, 전체 불일치/누락 사유를 표시한다.
A5에는 이 검사 결과를 포함한 게이트 응답을 전달한다. AI 의견은 차단을 변경하지 않는다.

## 검증

도메인별 최신 선택(생성 시각·ID), 다른 스테이지 배제, 누락·공백·불일치 동시 표시,
수동 통과·웨이버의 범위 제한, 일부 STA 보고서 제한에 대한 API/서비스 검증을 수행했다.
관련 테스트 91개와 프런트엔드 빌드를 통과했다.
`scripts/browser_gate_provenance_check.mjs`는 임시 인증 DB의 실제 게이트 응답을 사용한다.
AI 응답만 모의 처리하여 전달 입력과 320/390/1440px 화면 배치를 검증한다.

## 게이트 근거 JSON 내보내기

프로젝트 화면의 **게이트·근거 JSON 다운로드** 또는
`GET /projects/{project_id}/signoff-status/export?stage=...`를 사용한다.
조회 권한(viewer 이상)을 적용하고 다운로드 시점의 스테이지 상태를 새로 계산한다.
화면에 마지막으로 표시됐던 시점과 다운로드 시점 사이에 결과가 바뀔 수 있다.

형식은 `signoff/stage-gate-export/v1`이다. 프로젝트 ID, UTC 내보내기 시각, 게이트와
리비전 검사, 실제 선택된 최신 런의 상태·툴·메트릭·보관 결과·원본 해시·리비전,
현재 위반 상태/버전과 웨이버 사유/승인자를 포함한다. 날짜는 UTC로 내보낸다.
원본 파일, 전체 변경 이력, AI 의견은 별도이며 새 모델 호출을 하지 않는다.
사람의 승인이나 변경 불가능한 감사 기록을 의미하지 않는다.

게이트와 런의 근거는 하나의 SQL 조회로 함께 읽는다. 과거 런은 윈도 함수로 제외하고
원본 source_text 열은 조회하지 않는다. 일반 게이트 조회에도 같은 선택 로직을 사용한다.
파일명은 `project-{id}-{stage}-gate.json`이다. UTF-8 JSON 8 MiB 또는 선택된 런의
위반 합계 10,000건을 넘으면 413으로 거절하고 부분 파일을 반환하지 않는다.
`Cache-Control: no-store`와 `X-Content-Type-Options: nosniff`를 적용한다.

## 검증된 근거 패키지

프로젝트 화면의 **검증된 근거 패키지 다운로드** 또는
`GET /projects/{project_id}/signoff-package?stage=...`를 사용한다. 형식은
`signoff/evidence-package/v1`이며 현재 게이트가 선택한 정확한 런 ID, 리비전 검사,
메트릭, 위반·웨이버 상태와 각 런의 원본 보고서를 ZIP으로 묶는다.

서버는 패키지를 만들 때 원본 UTF-8 바이트의 SHA-256을 다시 계산한다. 원본이나 저장
해시가 없거나 두 값이 다르면 409로 거부한다. `manifest.json`의 `files`에는 ZIP 내부
경로, 바이트 수와 해시가 있고 `X-Signoff-Manifest-SHA256` 응답 헤더는 매니페스트
자체의 해시를 제공한다. 원본 합계나 압축 결과가 32 MiB 또는 위반 합계가 10,000건을 넘으면 413으로
거부한다. 리비전 누락·불일치는 숨기지 않고 매니페스트의 게이트 판정에 보존한다.

이 패키지는 보관된 바이트의 무결성과 선택 런을 재확인하기 위한 스냅샷이다. 벤더 서명,
실제 입력 설계의 동일성, 사람의 승인을 대신하지 않으며 AI 모델도 호출하지 않는다.

검증: 관련 API/서비스 테스트 53개, 프런트엔드 빌드, 임시 인증 DB 브라우저 검증 통과.
최신 런 단일 조회·원본 열 제외, 권한, 웨이버 귀속, 빈 스테이지, 크기 경계 및 위반 수 제한,
실제 다운로드 바이트 일치·오류 후 재시도·320/390/1440px 배치를 확인했다.
