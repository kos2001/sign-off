# 상용 서비스 수준 개선 작업

## 목표

Sign-off Hub의 MVP를 실제 설계 검토에 사용할 수 있는 관리·분석 서비스로 개선한다.
분석 정확도, 근거 추적, 검토 작업 흐름, 운영 안정성과 사용성을 함께 검증해야 한다.
현재 구현을 상용 EDA 엔진의 정확도와 동등하다고 간주하지 않는다.

## 2026-09-15: 위반 처리 흐름

- 취소해도 승인되던 prompt를 명시적인 저장/취소 폼으로 교체.
- 처리자·사유 필수, 공백 입력 거부, 저장 중 중복 클릭 방지, 요청 오류 표시.
- open → fixed/waived, fixed/waived → open 상태 변경 API.
- 상태 비교 후 갱신하여 이미 다른 상태로 처리된 요청에 409 응답.
- 변경 이력: 이전/다음 상태, 처리자, 사유, 시각. API에서 수정/삭제 경로를 제공하지 않음.
- 기존 웨이버 API도 동일한 이력 경로를 사용. 기존 DB에는 시작 시 새 테이블 생성.
- 이력 도입 전 웨이버는 해제할 때 원 승인 근거를 이력으로 옮겨 보존.
- 게이트는 기존 정책에 따라 재평가: open error/critical 차단, fixed/waived 제외.

검증: 위반 처리 API 회귀 테스트와 아래 브라우저 통합 검증 완료. 이 단계 당시 처리자 신원 확인은 미구현이었으며 아래 계정 인증 단계에서 확장했습니다.

## 2026-09-15: 프로젝트 위반 검토 화면

- `/projects/:id/violations`: 체크 이름·위치·설명·툴 검색, 상태·심각도·단계·도메인 필터.
- 서버에서 검색·집계·정렬·페이지 이동 처리, 페이지당 최대 100건.
- 단계·도메인별 최신 런을 먼저 선택한 뒤 위반 필터 적용. 과거 런 포함 옵션 제공.
- 검색 조건·페이지·선택 항목을 URL에 보존하고 브라우저 뒤로 가기/새로고침에서 복원.
- 선택한 위반 바로 아래에서 처리와 이력 검토. 검색 결과와 게이트 캐시 갱신.
- 빈 결과, 조회 실패와 재시도, 범위를 벗어난 페이지에서 첫 페이지 복귀.
- 모바일에서는 세로 항목 배치와 접이식 메뉴를 사용해 검토 내용이 잘리지 않도록 개선.

검증: 백엔드 79개 테스트 통과, 프런트엔드 빌드 통과.
별도 Chromium + 임시 SQLite DB에서 페이지 이동, URL 복원/뒤로 가기, 필터,
최신/과거 런, 검색, 취소 시 무변경, 승인→재오픈→수정 완료와 이력,
모바일 폼·메뉴·가로 잘림 없음, API 오류 표시와 복구, 런타임 오류 없음 확인.
실행 스크립트: `scripts/browser_review_check.mjs` (재현: `docs/browser-verification.md`).

## 2026-09-15: 실행 결과 비교

- `/projects/:id/compare`: 같은 프로젝트·도메인·단계의 두 런 선택, 기준/대상 교환.
- 지표의 기준값·대상값·숫자 차이 표시. 미등록과 null을 구분하고 숫자가 아닌 값에는 차이를 계산하지 않음.
- 위반은 체크 이름·위치로 대응: 대상에만 있음, 내용 변경, 기준에만 있음, 동일.
- 중복 항목을 집합으로 합치지 않고 동일 내용 우선으로 대응하여 개수를 보존.
  중복 키는 불확실한 대응임을 표시하며 자동으로 수정 완료나 웨이버를 전파하지 않음.
- 심각도·처리 상태·설명·웨이버 승인 근거의 변화 표시. 양쪽 원래 기록을 함께 조회.
- 실행 중 결과는 잠정 비교, 서로 다른 툴은 조건·단위 확인 안내.
- 실제 런 ID를 URL에 고정하여 새 실행이 등록되어도 공유 링크의 대상이 바뀌지 않음.
- 차이 유형 필터와 서버 페이지 이동. 실행 조합 변경 시 필터/페이지 초기화.
- 비교는 읽기 전용이며 기존 위반·승인 이력을 변경하지 않음.

검증: 전체 백엔드 테스트 91개, 프런트엔드 빌드 통과.
API 테스트는 중복/누락 위치/수치·bool·null/역방향 비교/페이지 이동/프로젝트 경계/
호환되지 않는 실행 거부/읽기 전용 동작을 확인.
Chromium 통합 검증은 지표 차이, 필터·페이지·URL 복원, 기준 교환, 새 실행 등록 후
대상 고정, 잠정 결과 갱신, 잘못된 링크 복구, API 실패 재시도와 모바일 배치를 확인.

## 2026-09-15: RTL 판정과 실행 근거

- CONDITIONAL을 passed로 저장하던 버그 수정: incomplete 상태와 분포 차트 반영.
- 필수 단계의 실패·생략·누락·중복을 검사하고 원본 RTL 근거가 없는 런은 RTL 게이트 차단.
- RTL 실행 소스와 SHA-256, 입력 리비전, 원래 결과를 별도 테이블에 보존.
- 서버 분석과 수동 입력·기존 데이터를 구분하고 캡처된 분석 결과의 덮어쓰기 차단.
- 위반 검토 이력은 유지하되 웨이버로 실패한 실행을 통과 결과로 바꾸지 않음.
- 실행 근거 조회·원본 코드 보기·JSON 다운로드, 모바일 배치와 키보드 스크롤 지원.
- 툴 시간 초과·실행 오류는 기록 가능한 실패로 변환.
- 최종 판정 없이 끊긴 스트림을 오류로 표시하고 실행 중 애니메이션 중단.

검증: 백엔드 102개 테스트, 프런트엔드 빌드 통과. 기존 SQLite 스키마 호환 테스트 포함.
브라우저에서 실제 스트리밍 RTL 실행 → incomplete 저장 → RTL 게이트 차단 → Pass 버튼 잠금 →
원본 소스/리비전/단계 결과 조회 → JSON 다운로드의 해시 확인, 모바일 표시와 스트림 중단 오류 검증.
이 단계 당시 테스트벤치 실행은 미지원이었습니다. 아래 테스트벤치 지원 단계에서 확장했습니다.
PostgreSQL enum 마이그레이션 안내는 제공했지만 실제 업그레이드 검증은 남아 있습니다.

## 2026-09-15: 동시 검토와 변경 버전

- 상태만 비교하던 저장을 상태+버전 비교로 강화. 상태가 원래대로 돌아온 경우도 오래된 요청 거부.
- PATCH와 기존 웨이버 POST 모두 expected_version 필수. 단건 조회 API에도 version 제공.
- 버전 증가·웨이버 변경·이력 추가를 한 트랜잭션으로 처리.
- SQLite의 반복/동시 시작을 지원하는 additive schema migration으로 기존 데이터 보존.
- 폼 시작 시 버전을 고정하고 충돌 시 자동으로 새 버전을 사용하지 않음.
- 충돌 후 이력을 확인하도록 저장 잠금. 초안은 앱 메모리에서 유지하여 필터로 행이 사라져도 복원.
  탭 새로고침·닫기를 넘어서 보존하지 않으며, 사용자 신원과 권한 확인은 아래 계정 인증 단계에서 추가했습니다.

검증: 백엔드 113개 테스트와 프런트엔드 빌드 통과.
동시 저장 중 한 요청만 성공하는지, 상태 왕복 후 이전 요청 거부, 실패한 커밋의 전체 롤백,
기존 SQLite 데이터 보존과 동시/반복 초기화를 확인.
실제 브라우저 두 창에서 충돌과 명시적 재검토, 사유 보존, 필터로 행이 사라진 뒤 초안 복원 확인.

## 2026-09-15: SQLite 운영 백업과 복원

- 실행 중인 DB의 커밋된 WAL 데이터를 포함하는 온라인 스냅샷 CLI 추가.
- ZIP에 DB와 매니페스트를 보관하고 SHA-256·크기·스키마·행 수·무결성·참조 관계 검증.
- 검증된 DB만 새 경로에 게시하며 기존 파일·심볼릭 링크·SQLite 보조 파일 덮어쓰기 차단.
- 검증·복원 과정은 앱 초기화나 마이그레이션을 실행하지 않음.
- [복구 절차](backup-recovery.md)에 전환, 롤백, 보관과 SQLite 전용 범위를 명시.

검증: 백엔드 132개 테스트 통과(백업 관련 19개 추가).
활성 WAL, 원본 근거·검토 이력·버전 보존, 손상·타 DB·고아 레코드 거부,
기존 스키마 보존과 실패 시 대상 미생성을 확인.
브라우저 검증용 DB를 실제 CLI로 백업·검증·복원하여 프로젝트 13개, 실행 51개,
위반 426개, 검토 이력 36개, 실행 근거 25개, 웨이버 1개의 전체 내용 일치 확인.
운영 서비스 전환 및 PostgreSQL 복구 검증은 아직 수행하지 않았습니다.

## 2026-09-15: 실제 RTL 테스트벤치 실행

- 동기/스트리밍 API와 분석 화면에 테스트벤치·명시적 최상위 모듈 입력 추가.
- Icarus 컴파일 및 실행, 정상 완료 마커와 오류 진단에 따른 보수적 pass/fail 판정.
- 프로세스별 실행 시간·출력 한도와 종료 시 프로세스 그룹 정리.
- 테스트벤치 원문·SHA-256·툴 버전·컴파일/실행 로그·종료 코드를 읽기 전용 근거에 보존.
- UI에서 대응 RTL+테스트벤치 예제 로드, 저장된 근거 조회와 JSON 다운로드 지원.
- 기본 실행 비활성. 명시적인 trusted_local 모드는 신뢰된 로컬 입력 전용이며 OS 격리가 아님.
  운영용 워커 격리는 아직 미구현이며 [실행 범위 문서](rtl-simulation.md)에 명시.

검증: 백엔드 151개 테스트 통과(시뮬레이션 관련 19개 추가), 프런트엔드 빌드 통과.
실제 Icarus로 정상 완료, 기능 검사 실패, assertion 오류, 컴파일 실패, 성공 마커 누락,
$stop, 무한 실행, 출력 한도 초과를 확인. 동기/스트리밍 저장·게이트·원본 잠금 검증.
실제 브라우저에서 예제 실행 → SIGNED_OFF 저장 → 테스트 변경으로 REJECTED 및 게이트 차단,
기존 성공 런의 테스트벤치 보존·다운로드 해시, 모바일 표시 확인.
기존 검토·충돌·실행 비교·실행 근거 브라우저 회귀도 통과.

## 2026-09-16: 계정 인증과 프로젝트 권한

- required 모드에서 세션 로그인과 모든 업무 API의 기본 접근 차단 적용.
- 프로젝트별 viewer/editor/approver/owner 역할과 구성원 관리 화면 추가.
- 런·위반·이력·실행 근거의 직접 ID 접근도 프로젝트 권한으로 제한.
- 웨이버 승인·해제는 approver 이상, 수정 완료 처리는 editor 이상에게 허용.
- 요청에 전달된 처리자 이름을 신뢰하지 않고 로그인 계정 이름과 ID를 서버에서 기록.
- 기존 직접 입력 이력의 인증 ID는 null로 보존하여 로그인 기록과 구분.
- HttpOnly 세션 쿠키, CSRF 토큰, 재로그인 세션 교체, 공유 DB 로그인 횟수 제한 추가.
- 비밀번호 재설정·계정 비활성화·전체 세션 폐기용 운영 CLI와 초기 관리자 안내 제공.
- 계정·역할 전환 시 캐시와 초안 정리, 에이전트 대화도 계정별 분리.
- 기본 local 모드는 기존 로컬 데모 동작을 유지하며 인증이 없음을 화면에 표시.

검증: 백엔드 163개 테스트 통과, 프런트엔드 빌드 통과.
미로그인 전체 업무 경로, 타 프로젝트 직접 ID 요청, 역할별 변경, 처리자 위조,
CSRF·쿠키·로그아웃·만료·비활성·권한 제거·비밀번호 재설정·로그인 제한·대화 분리 검증.
브라우저에서 계정 전환 시 초안 제거, 열람자 변경 차단, 승인 계정 ID 보존,
구성원 역할 변경과 모바일 화면 검증. 기존 로컬 모드의 위반 검토·충돌·비교·실행 근거 및
RTL 테스트벤치 브라우저 회귀도 통과. 실제 HTTPS·SSO·운영 보안 검토는 미완료입니다.

## 2026-09-16: 프로젝트 권한 감사 이력

- 구성원 권한 추가·변경·제거와 감사 이력을 같은 트랜잭션으로 저장.
- 대상 계정·처리 계정 ID·이전/이후 역할·시각을 보존하고 구성원 제거 후에도 유지.
- 신규 프로젝트 소유자 부여 및 CLI grant 기록. CLI는 로그인 신원이 없음을 구분.
- 동시 변경 시 이전 역할 비교로 충돌 감지. 동일 역할 재저장은 변경 이력을 추가하지 않음.
- 소유자/관리자 전용 이력 조회와 커서 기반 페이지 이동, 구성원 화면에 이력 표시.

검증: 백엔드 168개 테스트 및 프런트엔드 빌드 통과. 추가/변경/제거, 신원 위조 방지,
조회 권한, 커서 안정성, 커밋 실패 시 전체 롤백, 동시 변경 중 한 요청만 반영되는지 확인.

### 2026-09-19 · 사인오프 결정 step-up 인증

추가했다. 확인 직후 계정 행을 원자적으로 재검사해 비밀번호 변경·비활성화와의 경합을 차단하고,
확인 시각을 결정 SHA-256 및 휴대용 감사 원장에 결합한다. 실패는 비밀번호를 저장하지 않고 계정
보안 이력에 남기며 5분 단위 시도 제한을 적용한다. UI는 비밀번호 입력 전 결정 버튼을 비활성화하고
제출 뒤 입력값을 지운다. 로컬 데모·수집기 자동화에는 적용하지 않으며 AI는 자격 증명 확인이나
결정에 개입하지 않는다. 전체 백엔드 1,085개 테스트(1개 건너뜀)와 프런트엔드 프로덕션 빌드를
통과했다.

### 2026-09-19 · PostgreSQL 설치·업그레이드 CI 검증

운영 PostgreSQL용 psycopg 3 드라이버를 해시 고정 의존성에 추가하고 PostgreSQL 17 이미지를 digest로
고정했다. 레거시 마이그레이션의 PostgreSQL 비호환 `DATETIME`, `BOOLEAN DEFAULT 0` SQL을 dialect별
타입으로 수정하고 native `domain`·`runstatus` enum을 시작 잠금 안에서 자동 확장한다. CI는 임시
스키마에 축소된 레거시 enum과 기존 프로젝트 행을 만든 뒤 두 워커의 동시 초기화, 반복 초기화,
전체 테이블·인덱스·컬럼, 데이터 보존과 새 enum 값 저장을 실제 PostgreSQL에서 검사한다. 전체 SQLite
백엔드 1,085개 테스트(1개 건너뜀), PostgreSQL 마이그레이션 검증과 프런트엔드 프로덕션 빌드를
통과했다.
