# AI 검토 처리 용량

자동 A1/A2/A3/A5/V 검토와 런에 저장하는 검토는 하나의 호스트 로컬 슬롯 풀을 공유한다.
`SIGNOFF_REVIEW_MAX_CONCURRENT`는 기본 2이며 1–16 범위를 허용한다.
잘못된 값은 서버 시작 시 거절한다. RTL 실행 슬롯과는 독립적이다.

`SIGNOFF_REVIEW_SLOT_DIR`는 기본적으로 OS 임시 디렉터리의 `signoff-reviews-<uid>`다.
운영 시 같은 호스트의 API 작업자들은 **같은 디렉터리와 같은 한도**를 사용해야 한다.
컨테이너를 여러 개 사용하면 동일한 로컬 볼륨을 공유해야 하며, 별도 파일시스템의 슬롯은
서로 조정되지 않는다. 디렉터리 0700, 슬롯 파일 0600으로 서비스 사용자만 접근하게 한다.
실행 중 슬롯 파일을 삭제·교체하지 않는다. 한도·디렉터리 변경은 진행 중 요청을 비운 뒤
모든 작업자에 동일하게 적용한다.

커널 파일 잠금을 비차단 방식으로 획득한다. 슬롯이 없으면 공급자 클라이언트를 만들거나
모델을 호출하지 않는다. 일반 검토 결과에는 `available=false`, `error=review_capacity`를
반환하고 UI에서 연결 오류와 다른 **검토 처리 한도 도달** 상태로 표시한다.
이는 큐에 들어간 작업이 아니다. 자동 재시도하지 않으며 사용자가 잠시 후 다시 요청한다.
조건 미해당 결과에는 슬롯이 필요하지 않다.

A5와 V는 각각 호출 시 슬롯을 얻는다. A5가 실행되지 않으면 V는 생략된다.
A5가 성공했지만 V가 한도에 걸리면 A5 의견은 유지하고 V 미완료를 표시한다.
게이트 재시도는 기존과 같이 A5부터 전체 순서를 다시 실행한다.

저장 검토는 요청 접수를 먼저 보존하므로 한도에 걸린 요청도 `failed` 기록으로 남는다.
입력·요청자와 미시작 사유가 보존되고, 같은 요청 키는 같은 기록을 반환한다.
재검토는 화면에서 새 요청으로 실행한다. 승인이나 원래 분석 결과는 바뀌지 않는다.

성공·오류·타임아웃·취소 시 슬롯을 반환한다. 프로세스 강제 종료 시에도 커널이 잠금을
해제한다. 이는 API 측 동시 호출 한도이며, 취소 후 공급자가 내부 실행을 계속하는지까지
증명하거나 제어하지 않는다. 분산 작업 큐, 사용자별 공정 배분, 요청 빈도 제한은 별도다.

검증: 관련 테스트 63개와 프런트엔드 빌드 통과. 별도 프로세스 잠금 공유, 강제 종료 후
복구, 취소 정리, 설정 범위, 안전하지 않은 파일 거절, 자동/저장 검토 공유와 새 요청 복구를 확인했다.
`scripts/browser_review_capacity_check.mjs`는 임시 인증 API의 실제 슬롯을 점유하여
한도 응답, A5/V 생략 관계, 저장 실패 재조회와 320/390/1440px 배치를 검증한다.
