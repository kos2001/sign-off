# RTL 테스트벤치 실행

분석 화면의 **테스트벤치 (선택)**에서 단일 파일 SystemVerilog 테스트벤치와
최상위 모듈 이름을 입력합니다. **펄스 동기화 검증 예제 불러오기**는 RTL과 대응하는
테스트벤치를 함께 불러옵니다. 프로젝트를 선택하면 원본 결과와 함께 저장합니다.

## 판정 계약

- Icarus로 `design.sv`와 `testbench.sv`를 함께 컴파일하고, 명시한 테스트벤치 모듈을 실행합니다.
- 자체 검사에서 불일치는 `$fatal(1, "이유")`로 보고합니다.
- 모든 검사를 마친 뒤 `$display("SIGNOFF_TEST_PASS"); $finish;`로 종료합니다.
- 컴파일 실패, 비정상 종료, `$stop`, `ERROR:`/`FATAL:` 진단, 시간 초과,
  로그 한도 초과, 성공 마커 누락은 필수 simulate 단계의 fail입니다.
- 성공 마커가 있어도 실패 진단이나 비정상 종료가 있으면 fail입니다.
- 테스트벤치 미제공, 서버에서 실행 비활성, 툴 미설치는 skip이며 전체 판정은 최대 CONDITIONAL입니다.
- 시뮬레이션을 포함한 모든 필수 단계가 pass여야 SIGNED_OFF로 저장됩니다.

Pass는 제출한 테스트벤치가 위 계약에 따라 완료됐다는 의미입니다. 테스트 품질,
기능 커버리지, CDC 메타안정성, 모든 입력 조합의 정확성이나 파운드리 sign-off 인증을
자동으로 보장하지 않습니다. 검토자는 설계 리비전과 테스트 내용을 확인해야 합니다.

`vvp -N`으로 대화형 중단을 막고 `$stop`을 오류 종료로 취급합니다.
근거: [Icarus 공식 vvp 옵션 문서](https://steveicarus.github.io/iverilog/usage/vvp_flags.html).

## 서버 설정과 실행 범위

기본값은 시뮬레이션 실행 비활성입니다. 신뢰할 수 있는 소스만 다루는 로컬 개발 서버에서:

```sh
cd backend
SIGNOFF_SIMULATION_MODE=trusted_local .venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
```

`iverilog`와 `vvp`가 PATH에 있어야 합니다. lint에는 verilator, 합성에는 yosys가 별도로 필요합니다.
시뮬레이션 컴파일·실행 각각 30초, 린트·합성 각각 60초, 각 툴의 stdout/stderr 합계 128 KiB로 제한하고 종료 시 프로세스 그룹을 정리합니다.
POSIX 실행 환경을 대상으로 합니다. 사용자 지정 파일 경로, 컴파일 옵션, VPI 모듈,
다중 파일 프로젝트, 파형 파일 수집은 API에서 지원하지 않습니다.

**trusted_local은 OS 샌드박스가 아닙니다.** HDL 시스템 태스크의 파일·프로세스 접근,
전체 메모리·디스크 사용과 네트워크를 격리하지 않습니다. 아래의 프로세스별 자원 상한을
적용하지만 인터넷이나 신뢰하지 않는 사용자에게 이 모드를
개방하면 안 됩니다. 다중 사용자 운영에는 격리된 워커와 자원·동시 실행 제한을 적용해야 하며
현재 구현에는 해당 운영 격리가 포함되지 않습니다. 기존 lint/합성 실행도 별도 격리 검증 대상입니다.

## API와 보존 근거

`POST /analysis/rtl-signoff`와 `/analysis/rtl-signoff/stream`에 다음 두 필드를 함께 전달합니다.

```json
{
  "code": "module ... endmodule",
  "testbench": "module tb; ... endmodule",
  "testbench_top": "tb",
  "project_id": 1,
  "design_revision": "commit-id"
}
```

테스트벤치는 최대 500,000자이며 빈 입력을 거부합니다. 최상위 모듈은 단순 Verilog 식별자입니다.
두 필드 중 하나만 보내면 422를 반환합니다. 기존 테스트벤치 없는 요청은 그대로 지원합니다.
스트림에는 simulate 시작·완료 이벤트가 추가됩니다.

`result.simulation`은 정규화한 테스트벤치 원문과 SHA-256, 최상위 모듈,
Icarus 버전 출력, 컴파일·실행 로그와 종료 코드, 실패 이유를 보존합니다.
프로젝트에 기록하면 기존 읽기 전용 `RunEvidence.result` JSON에 함께 저장되므로
추가 DB 스키마 변경이 필요하지 않습니다. 실행 근거 화면과 JSON 다운로드로 재확인할 수 있습니다.
백업·복원에도 이 JSON이 포함됩니다. 시뮬레이션 실패는 런 상태와 게이트에 반영되며,
현재 별도 위반 레코드로 변환하지는 않습니다.

## RTL 분석 동시 실행 제한

동기 API와 스트리밍 API가 동일한 호스트 실행 슬롯을 사용합니다.
`SIGNOFF_RTL_MAX_CONCURRENT`는 1–16이며 기본값은 2입니다. 잘못된 값은 서버 시작 시 거부합니다.
실행 중인 요청으로 슬롯이 모두 차면 툴 실행과 런 저장 전에 HTTP 429와 `Retry-After: 5`를
반환합니다. 대기열에 넣거나 자동 재실행하지 않습니다. 화면에서 입력은 유지되며 다시 실행할 수 있습니다.

Unix 커널 파일 잠금으로 API 워커 사이에 슬롯을 공유합니다.
기본 잠금 디렉터리는 OS 임시 디렉터리의 `signoff-rtl-<uid>`입니다. 같은 OS 사용자로 실행하는
서버들은 기본적으로 이를 공유합니다. `SIGNOFF_RTL_SLOT_DIR`로 전용 경로를 지정할 수 있으며,
실행 사용자 소유의 0700 디렉터리여야 합니다. 모든 워커에 같은 경로와 실행 개수를 설정하세요.
실행 중에는 잠금 파일·디렉터리를 삭제하거나 용량 설정을 바꾸지 않습니다. 설정 변경은 워커를
종료한 뒤 일괄 적용합니다. 컨테이너별 별도 파일시스템이나 서로 다른 호스트는 이 제한을 공유하지 않습니다.

스트리밍 연결 종료 시 다음 단계를 시작하지 않으며 현재 실행 중인 단계가 반환된 뒤 슬롯을
반환합니다. 즉, 연결 종료를 즉시 툴 강제 종료로 간주하지 않습니다. 이미 진행 중인 결과 저장은
완료될 수 있습니다. 정상 종료·예외·헤더 전송 실패에도 슬롯을 반환합니다.
프로세스 종료 시 커널 잠금은 해제되지만, 비정상 종료 후 남은 툴 자식 프로세스 정리는 운영
프로세스 관리자의 별도 책임입니다.

이 제한은 CPU·메모리·디스크·네트워크 격리나 사용자별 공정한 할당을 제공하지 않습니다.
trusted_local의 실행 신뢰 범위는 그대로이며 다중 사용자 운영용 워커 격리는 남아 있습니다.

검증: `backend/tests/test_rtl_admission.py`의 프로세스 간 공유, 프로세스 종료 후 잠금 복구,
동기/스트리밍 공통 제한, 연결 종료 중 슬롯 유지와 다음 단계 중단, 스트림 시작 전 실패 정리.
`scripts/browser_rtl_capacity_check.mjs`는 별도 테스트 서버에서 슬롯을 점유한 상태의 `busy`와
반환한 뒤의 `available` 모드를 실행해 실제 HTTP 상태, RTL 입력 보존과 실행 버튼 복구를 확인합니다.

## 공통 툴 실행 래퍼

Verilator, Yosys, Icarus 컴파일과 vvp 실행은 같은 출력 제한·마감 시간·프로세스 그룹 정리
구현을 사용합니다. 표준 입력은 닫으며 실행 작업 디렉터리는 각 요청의 임시 디렉터리입니다.
시간 또는 출력 상한을 넘기면 툴 종료 코드가 0이더라도 해당 단계를 실패로 판정합니다.
표준 출력/오류를 무제한 메모리 버퍼에 모으지 않으며, UTF-8 오류 문자를 치환한 뒤의
응답 로그도 같은 바이트 상한을 적용합니다.

툴이 종료된 뒤에도 동일 프로세스 그룹의 자식이 남으면 정리합니다. 자식이 출력 파이프를
계속 열고 있는 경우에도 마감 시간이 적용됩니다. 별도 프로세스 그룹으로 이탈한 프로세스,
파일 접근 격리는 이 래퍼의 보장 범위에 포함되지 않습니다.

`backend/tests/test_rtl_process.py`는 실제 테스트 프로세스로 출력 폭주·비정상 UTF-8·
표준 출력/오류 합산·시간 초과·부모 종료 후 자식 정리 및 린트/합성 실패 전달을 검사합니다.

## 툴 프로세스별 자원 상한

공통 실행기는 격리 모드 Python(`-I`)으로 별도 런처를 시작하고, 상한을 적용한 뒤 툴로
`exec`합니다. [Python subprocess 문서](https://docs.python.org/3/library/subprocess.html)의
스레드 안전성 주의에 따라 `preexec_fn`을 사용하지 않으며 서버 자체의 상한은
변경하지 않습니다. 상한을 설정하지 못하면 툴을 시작하지 않고 실패합니다.

| 자원 | 기본 상한 |
| --- | --- |
| CPU 시간 | 해당 툴의 벽시계 제한을 초 단위 올림한 값 + 1초 (린트/합성 61초, 시뮬레이션 31초) |
| 파일 하나의 크기 | 64 MiB |
| 열린 파일 디스크립터 | 256개 |
| 코어 덤프 | 0바이트 |
| 가상 주소 공간 | Linux에서 1 GiB; macOS에서는 적용하지 않음 |

상위 프로세스에 더 낮은 제한이 있으면 그 값을 유지하며, soft/hard 상한을 함께 낮춥니다.
일반 자식 프로세스가 제한을 상속합니다. Linux 메모리 제한은 RSS가 아닌 가상 주소 공간이며
할당 실패로 나타날 수 있습니다. 제한으로 비정상 종료한 툴은 단계 실패로 처리합니다.
이 동작은 [Python resource 문서](https://docs.python.org/3/library/resource.html)의
Unix 프로세스별 자원 제한을 사용합니다.

프로세스 트리 전체의 CPU/메모리 합계, 전체 디스크 용량·파일 수, 파일 읽기 권한,
네트워크와 권한 상승을 제한하는 기능은 아닙니다. 따라서 trusted_local 정책은 유지하며
다중 사용자 운영에는 별도 워커 격리가 필요합니다.

검증은 macOS의 실제 Verilator/Yosys/Icarus 회귀와 파일 크기·CPU·자식 상속·서버 제한 보존,
별도 Linux 컨테이너의 메모리 할당 실패·파일 크기·CPU·파일 디스크립터 상한을 포함합니다.
Linux 메모리 테스트는 macOS pytest에서는 건너뛰며 Linux CI에서 실행 대상입니다.

## 실제 Linux RTL 툴 통합 검사

저장소 루트에서 Docker 검증 이미지를 만들고, 네트워크가 없는 임시 컨테이너로 실행합니다.

```sh
docker build -f backend/Dockerfile.rtl-check -t signoff-rtl-check:local backend
docker run --rm --network none --read-only \
  --tmpfs /tmp:rw,exec,size=512m --memory 2g --cpus 2 --pids-limit 128 \
  signoff-rtl-check:local
```

이미지는 비관리자 UID로 실행되며 소스와 테스트만 포함합니다. 호스트 DB·환경 파일·가상 환경은
빌드 컨텍스트에서 제외하고 런타임 호스트 디렉터리는 마운트하지 않습니다. 필수 툴 네 개의
실행 파일과 버전 명령을 먼저 확인한 뒤 실행기·시뮬레이션·사인오프·동시 실행 제한 테스트를
실행합니다. 툴이 없을 때 검사 일부를 건너뛰어 성공으로 보이는 것을 방지합니다.
임시 디렉터리의 `exec`는 테스트가 생성하는 가짜 툴 실행 파일에 필요합니다.
프로세스 정리 검사는 이미지에 포함한 `ps`로 자식 종료를 확인합니다.

Python 기반 이미지는 digest로 지정하지만 apt/pip 의존성은 빌드 시점 저장소를 사용합니다.
정확한 실행 환경 보관이 필요하면 생성한 이미지 ID와 버전 출력을 함께 기록하세요.
이 이미지는 검증용이며 운영용 워커 배포·작업 큐·격리 정책을 구현하는 것은 아닙니다.

2026-09-16 검증 결과: Linux ARM64, Python 3.11.16, Icarus/vvp 12.0,
Verilator 5.032, Yosys 0.52에서 **61개 통과, 건너뜀 없음** (ASGI 연결 종료 회귀 포함).
PATH에서 툴을 제외하면 테스트 시작 전에 종료 코드 1로 실패하는 것도 확인했습니다.
검증 이미지 ID: `sha256:784272eefcd39d0d6a22d0ef21230fd61fb296e74c54f953b9cb577e64220d07`.
이 결과는 로컬 Docker의 ARM64 검증이며 GitHub Actions나 Linux AMD64 실행 결과는 아닙니다.
기존 실제 Icarus 시뮬레이션과 RTL 래더 테스트도 동일 실행 래퍼로 수행합니다.
합성 통계에서 플립플롭 수와 래치 수는 별도로 집계합니다.
