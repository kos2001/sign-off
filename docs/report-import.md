# OpenSTA 보고서 가져오기

Synopsys PrimeTime 또는 Cadence Tempus 결과는 [상용 STA 경로 JSON 가져오기](commercial-sta-import.md)를
사용합니다. 이 페이지의 OpenSTA 고유 JSON과 상용 툴 교환 형식을 서로 바꾸어 해석하지 않습니다.

프로젝트의 **보고서 가져오기**에서 OpenSTA 버전, 설계 리비전, 시나리오/코너와 스테이지를
입력한 뒤 JSON 파일을 선택하거나 내용을 붙여 넣습니다. **가져오기 미리보기**는 저장하지
않습니다. 경로·위반 수·슬랙을 확인하고 **런으로 저장**하면 STA 런, 원본 근거와 위반을 함께
저장합니다. 프로젝트 편집자 이상이 가져올 수 있으며 열람자는 저장된 근거를 조회할 수 있습니다.

## 지원하는 출력

설계와 제약을 로드한 OpenSTA에서 다음 출력 형식을 사용합니다.

```tcl
report_checks -format json > timing.json
```

`checks` 배열과 각 경로의 `type`, `path_type` (`min`/`max`), `path_group`, `startpoint`,
`endpoint`, `source_path` 핀 목록 및 제약된 경로의 `slack`을 읽습니다. 시간 값은 초 단위이며
화면·지표에서는 ps로 변환합니다. `unconstrained` 경로에는 slack이 없어야 합니다.
경로 시작/끝과 핀 목록이 일치하지 않거나 일부 경로가 잘못되면 전체 가져오기를 거부합니다.
중복 JSON 키, NaN/Infinity, 잘린 JSON, 지원하지 않는 구조도 조용히 건너뛰지 않습니다.

UTF-8 JSON 최대 2,000,000바이트와 1,000개 경로를 지원합니다. BOM과 줄바꿈은 원본에
그대로 보존하며 SHA-256은 보존한 원본 UTF-8 바이트를 대상으로 계산합니다.
기타 출력 필드와 경로 상세는 원본 JSON에 유지합니다. 원본은 실행 코드로 평가하지 않습니다.

## 경로 상세와 클록 경로

타이밍 경로 화면에서 데이터 경로와 `source_clock_path`, `target_clock_path`를 구간별로
탐색할 수 있습니다. 구간별 핀은 100개씩 표시하며 선택한 구간과 페이지는 URL의 `section`,
`point_offset`으로 복원됩니다. 시작·끝 클록 에지와 OpenSTA가 보고한 `crpr`, `margin`,
`path_margin`, `path_delay`, `multi_cycle_path`도 원본 보고 값으로 표시합니다. 시간 값은 ps로
변환하지만 슬랙을 다시 계산하지 않습니다. 클록 경로가 없으면 미보고와 빈 목록을 구분하며,
미보고 값을 0으로 취급하지 않습니다.

상세 API는 응답 전에 보존 원본의 SHA-256을 확인하고 원본을 다시 파싱해 저장된 경로 목록과
일치하는지 검증합니다. 손상되거나 불일치하는 근거는 409로 거부합니다. 이 탐색은 읽기 전용이며
AI 검토를 호출하지 않습니다. 클록 간 도착 시간 차이는 스큐로 추정하지 않으며, 전체 SDC 제약과
계산 항목의 적용 순서는 단일 경로 보고서만으로 복원하지 않습니다.

호환성 기준은 OpenSTA 커밋 `d97587f669b4f169be7132346df70e7d634500c3`의
[공식 JSON 출력 구현](https://github.com/parallaxsw/OpenSTA/blob/d97587f669b4f169be7132346df70e7d634500c3/search/ReportPath.cc)과
[report_json1 회귀 출력](https://github.com/parallaxsw/OpenSTA/blob/d97587f669b4f169be7132346df70e7d634500c3/test/report_json1.ok),
[report_json2 회귀 출력](https://github.com/parallaxsw/OpenSTA/blob/d97587f669b4f169be7132346df70e7d634500c3/test/report_json2.ok)입니다.
공식 출력 두 파일을 읽어 1개 경로의 9,550 ps 변환과 빈 경로 결과를 확인했습니다.
OpenSTA 바이너리의 신규 실행이나 다른 버전 전체에 대한 호환성 검증은 수행하지 않았습니다.

## 판정과 근거의 의미

- 음수 슬랙이 있으면 `failed`, 그 외에는 `incomplete`로 저장합니다.
- 음수 슬랙 경로는 오류 위반, 제약 없는 경로는 경고 위반으로 등록합니다.
- `reported_paths`, `violating_paths`는 보고된 경로 수이며 중복 경로도 각각 셉니다.
  `worst_reported_slack_ps`는 보고된 경로의 최솟값입니다. 전체 설계 WNS/TNS나 위반 종점 수가 아닙니다.
- 보고서는 경로 선택·개수 제한이 있을 수 있어 전체 STA 검증 범위를 증명하지 않습니다.
  위반이 없거나 모두 웨이버 처리되어도 이 근거만으로 게이트를 통과하지 않습니다.
- 원본, 파서 버전, 정규화한 경로, 입력된 툴 버전·코너·리비전 및 업로드 계정을 보존합니다.
  툴 버전과 리비전은 업로더가 입력한 값이며 외부 툴 실행의 진위를 검증한 서명이 아닙니다.
- 저장된 결과·원본은 API에서 수정할 수 없습니다. 새 보고서는 새 런으로 가져옵니다.
  위반의 수정 완료·웨이버·재오픈은 기존 검토 이력으로 별도 기록합니다.
- 런 비교는 보고서에 포함된 경로 기준의 잠정 비교입니다. 경로의 핀·시작/끝·종류·그룹·클록으로
  식별하고 숫자 변화나 보고서 순서로 식별자가 바뀌지 않습니다. 코너·경로 선택 조건도 확인하세요.
  경로 삭제를 실제 설계 수정 완료로 간주하지 않습니다.

## API와 재시도

`POST /projects/{project_id}/imports/opensta/preview`와
`POST /projects/{project_id}/imports/opensta`는 같은 JSON 입력을 받습니다.

- `import_id`: 클라이언트가 생성한 UUID. 같은 저장 작업을 재시도할 때 유지합니다.
- `stage`, `filename`, `tool_version`, `design_revision`, `scenario`, `source_text`.

미리보기에는 DB 변경이 없습니다. 저장 요청에서도 원문을 다시 파싱합니다.
같은 프로젝트·import_id·입력을 다시 보내면 기존 런을 반환합니다. 같은 ID로 다른 내용을
보내면 409입니다. 동시 요청도 하나의 런만 남기며 런·위반·근거·재시도 기록은 한 트랜잭션입니다.
`run_evidence`를 사용하고 새 `report_imports` 테이블은 시작 시 생성되며 SQLite 백업에 포함됩니다.

## 검증

`backend/tests/test_report_import.py`는 단위 변환, 잘못된 입력, 중복 경로, BOM/줄바꿈,
원본 보존, 권한과 업로드 신원, 불변 결과, 웨이버 후 게이트 차단, 동시 재시도,
저장 실패 롤백, 순서가 바뀐 보고서 비교를 검사합니다.

[인증 테스트 seed](authentication.md#재현-가능한-브라우저-검증)로 만든 별도 DB를 사용하고,
API 18001 / 프런트엔드 15174 등 사용자 서버와 다른 포트에서 실행합니다.

```sh
SIGNOFF_AUTH_FIXTURE=/path/to/disposable-fixture.json \
  SIGNOFF_TEST_UI=http://127.0.0.1:15174 \
  node scripts/browser_import_check.mjs /absolute/path/to/playwright/index.mjs
```

브라우저 검증은 합성 보고서를 업로드하여 오류 표시, 미리보기 무효화, 저장, 읽기 전용 상태,
업로드 계정, 다운로드 원본 해시와 모바일 레이아웃을 확인합니다. 사용자 프로젝트 DB에서
실행하지 않습니다. 검증 후 테스트 서버와 임시 DB·자격증명을 폐기합니다.

텍스트 보고서, PrimeTime/Tempus, 제약·라이브러리·넷리스트·기생성분 묶음 검증,
전체 코너의 검증 범위 정책과 툴 실행 서명은 남아 있습니다.

## 저장한 타이밍 경로 탐색

프로젝트 런의 **타이밍 경로** 또는 가져오기 성공 화면의 **타이밍 경로 탐색**으로 이동합니다.
`/runs/{run_id}/paths` 화면에서 시작점·끝점·그룹을 검색하고 min/max, 슬랙 조건으로 필터링합니다.
기본은 슬랙 낮은 순이며 같은 슬랙은 원본 경로 번호 순서로 정렬합니다. 제약 없는 경로는 슬랙
정렬에서 마지막에 표시합니다. 검색 결과는 25개씩 이동하며 원본 경로 번호를 유지합니다.

경로를 선택하면 데이터 경로의 핀, 인스턴스, 셀, 넷, 도착 시간과 슬루를 확인합니다.
핀은 원본 순서대로 100개씩 조회합니다. 누락되거나 유효한 숫자가 아닌 시간 값은 0으로
대체하지 않습니다. 클록 경로 전체와 기타 출력 필드는 원본 근거 JSON에서 확인할 수 있습니다.
화면의 min/max를 특정 setup/hold 체크 유형으로 임의로 바꾸지 않습니다.

검색 조건, 페이지, 선택 경로와 핀 페이지를 URL에 보존합니다. URL을 공유해도 해당 프로젝트의
열람 권한이 있어야 조회할 수 있습니다. 경로 탐색은 원본·위반 상태를 수정하지 않습니다.

- `GET /runs/{run_id}/timing-paths`: `q`, `path_type=min|max`,
  `status=all|violated|met|unconstrained`, `slack_min_ps`, `slack_max_ps`,
  `sort=slack_asc|slack_desc|report`, `offset`, `limit`.
  limit은 1–100, offset은 0–1000입니다. 전체 보고된 수와 필터 후 수를 별도로 반환합니다.
- `GET /runs/{run_id}/timing-paths/{path_index}`: 원본 1부터 시작하는 경로 번호.
  `point_offset`은 0–10000, `point_limit`은 1–200이며 기본 100개입니다.
- 가져온 타이밍 경로가 없는 수동/RTL 런에는 409, 존재하지 않는 경로나 접근할 수 없는 런에는
  404를 반환합니다. 잘못된 필터나 범위는 422입니다.

`backend/tests/test_timing_paths.py`와 `scripts/browser_timing_paths_check.mjs`로 검색·정렬,
페이지 경계, 단위 변환, 미보고 값, 읽기 전용과 권한, URL 복원 및 모바일 표시를 검증합니다.
브라우저 스크립트는 위의 별도 테스트 DB·포트·QA 자격증명 환경변수를 사용합니다.

### 슬랙 범위 검색

**슬랙 하한 (ps)**과 **슬랙 상한 (ps)**에 숫자를 입력하고 **검색**을 누릅니다.
빈칸은 해당 방향 제한 없음입니다. 경계값은 포함하므로 하한 -10, 상한 0은
-10 ps와 0 ps를 모두 포함합니다. 한쪽 이상을 지정하면 슬랙이 없는 경로는 제외합니다.
0만 조회하려면 두 값에 모두 0을 입력합니다. 기존 텍스트·유형·슬랙 조건 필터와 함께 적용되며,
‘제약 없음’과 수치 범위를 함께 지정하면 결과가 없습니다.

API도 `slack_min_ps=-10&slack_max_ps=0`을 받습니다. 값은 유한한 ps 단위 숫자이며
지수 표기를 지원합니다. NaN/Infinity 또는 하한이 상한보다 큰 범위는 422로 거부합니다.
반올림하지 않은 저장 슬랙에 비교하며 전체 보고된 경로 수는 바뀌지 않습니다.

범위를 URL에 보존하고 적용된 범위를 목록 위에 표시합니다. 검색 적용 시 결과·핀 페이지와
선택 경로를 초기화합니다. 입력만 편집한 상태에서는 기존 적용 결과가 유지되며, 잘못된 범위는
오류를 표시하고 적용하지 않습니다. URL의 잘못된 범위로 조회가 실패하면 **검색 초기화**로
복구할 수 있습니다. 범위 조회는 근거·위반 상태를 수정하지 않습니다.

### 검색 결과 요약

목록 위의 요약은 현재 페이지뿐 아니라 검색 조건에 맞는 전체 경로를 집계합니다.
음수 슬랙·0 이상 슬랙·제약 없는 경로의 수와 최악 보고 슬랙을 표시합니다.
페이지나 정렬만 바꾸면 요약은 유지되고 검색 조건을 바꾸면 다시 계산합니다.
결과가 없거나 모두 제약 없는 경로이면 최악 슬랙은 **없음**으로 표시합니다.
작은 음수도 추가 반올림하지 않습니다.

목록과 JSON 내보내기의 `summary`는 `violated_paths`, `met_paths`,
`unconstrained_paths`, `worst_slack_ps`를 제공합니다. 앞의 세 개 합계는 `total`과 같으며,
보고된 유효 슬랙이 없으면 `worst_slack_ps`는 null입니다. 원본 전체 경로 수는 별도의
`reported_total`로 유지합니다. 경로 보고서의 집계이므로 전체 설계의 검증 통과나
고유 종점 수를 뜻하지 않습니다.

### 검색 결과 JSON 내보내기

목록의 **검색 결과 JSON 내보내기**로 적용된 검색 조건에 맞는 전체 경로를 저장합니다.
화면의 25개 페이지 제한을 적용하지 않습니다. 아직 검색을 누르지 않은 편집 중 값은
적용되지 않습니다. 결과가 없으면 경로 수 0과 빈 배열을 명시한 파일을 생성합니다.
실패하면 파일을 만들지 않고 오류를 표시하며 같은 버튼으로 재시도합니다.

`GET /runs/{run_id}/timing-paths/export`는 목록과 같은 검색·범위·정렬 인자를 받습니다.
프로젝트 열람 권한이 필요하며 임의 실행 상태나 원본 근거를 변경하지 않습니다.
파일명은 `run-{run_id}-timing-paths.json`, 응답은 JSON 첨부와 `Cache-Control: no-store`입니다.

- `format`: `signoff/timing-path-export/v1`, `exported_at`: UTC 내보내기 시각.
- `run`: 런·프로젝트 식별자 및 실행 정보.
- `report`: 보고서 출처, 파서, 원본 SHA-256, 설계 리비전, 제출 메타데이터와 검증 범위.
- `filters`: 적용한 검색 조건과 정렬. 페이지 offset/limit은 포함하지 않습니다.
- `units`: `slack_ps`의 단위 ps.
- `reported_total`: 원본 보고 경로 수, `total`: 검색 결과 수, `items`: 결과 전체.

원본 경로 번호, 핑거프린트, 누락 슬랙의 null을 보존합니다. 원본 JSON과 핀 상세는 이
요약 내보내기에 포함하지 않으며, **실행 근거 → 근거 JSON 다운로드**로 따로 보관합니다.
원본 해시는 입력 보고서를 식별하며 이 파일의 서명이나 전체 STA 검증의 완료를 증명하지 않습니다.

### 스프레드시트용 CSV 내보내기

**검색 결과 CSV 내보내기**는 JSON과 같은 적용 필터·정렬의 전체 경로를 한 행씩 저장합니다.
API는 같은 경로에 `format=csv`를 지정합니다. 기본 형식은 JSON이며 다른 형식은 422로 거절합니다.
파일명은 `run-{run_id}-timing-paths.csv`, 인코딩은 한글 호환을 위한 UTF-8 BOM입니다.
프로젝트 viewer도 내보낼 수 있고 프로젝트 외부 사용자는 접근할 수 없습니다.

- 행마다 런·프로젝트·스테이지, 원본 해시·리비전·파일명·시나리오·툴 버전·검증 범위를 포함합니다.
- `filtered_total`, `reported_total`, `filters_json`으로 선택 범위를 남깁니다.
- 경로 번호·유형·상태·`slack_ps`·시작점·끝점·그룹·검사 유형·핑거프린트를 포함합니다.
- 미보고 슬랙은 빈칸, 음수 및 작은 슬랙은 반올림하지 않은 숫자로 저장합니다.
- 결과가 없으면 열 제목만 저장합니다. 빈 결과의 필터/출처까지 보관하려면 JSON을 사용하세요.

쉼표와 따옴표는 CSV 규칙으로 인용합니다. `=`, `+`, `-`, `@` 등으로 시작해 수식으로
해석될 수 있는 문자열에는 작은따옴표를 앞에 붙입니다. 숫자 슬랙과 저장된 원본은 변경하지 않습니다.
스프레드시트에서 이 보호 문자를 지우거나 재저장하면 텍스트 해석이 달라질 수 있습니다.
정확한 원문과 구조화된 근거는 JSON으로 보관하세요. CSV에는 핀별 상세가 포함되지 않습니다.

## 수치 표시와 비교 정밀도

JSON 숫자를 배정밀도 부동소수점으로 읽을 때 무한대가 되거나, 0이 아닌 원래 값이
0으로 소실되면 미리보기·저장을 422로 거부합니다. 예를 들어 `-1e-400`이 `-0.0`으로
바뀌어 위반 수가 0이 되는 것을 방지합니다. 슬랙뿐 아니라 핀 도착 시간 등 보고서의 모든
실수 표기에 적용합니다. `0e-400` 같은 정확한 0과 표현 가능한 작은 음수는 허용합니다.
원본 값의 자릿수 전체를 보존하는 임의 정밀도 산술은 제공하지 않습니다.
이 검증은 새로 가져오는 보고서에 적용하며 이미 저장된 근거를 소급 수정하지 않습니다.

가져오기 미리보기, 경로 목록과 상세의 슬랙·도착 시간·슬루는 서버에서 받은 숫자를
화면에서 추가 반올림하지 않습니다. 예를 들어 -1e-17초는 -0.00001 ps로 표시되어
음수 위반이 0처럼 보이지 않습니다. 시간 단위 변환은 배정밀도 부동소수점 연산이며,
원본 JSON의 십진 표기 자체는 저장된 보고서에서 확인합니다.

새로 저장하는 위반 설명도 슬랙 값으로 다시 변환했을 때 같은 부동소수점 값이 되도록
기록합니다. 따라서 기존 12자리 표시에서는 같아 보이던 서로 다른 슬랙도 실행 비교의
‘내용 변경’으로 구분합니다. 짧은 표기로 값이 보존되는 기존 설명 형식은 유지합니다.
이미 저장된 근거와 위반 설명은 소급 수정하지 않으므로, 이전 기록에 반올림된 설명이
있으면 원본 근거의 경로 값을 함께 확인해야 합니다.

API 회귀 검사는 미리보기→저장→근거→경로 목록/상세의 수치 일치와 12자리 이후의
슬랙 변화 비교를 확인합니다. `scripts/browser_import_check.mjs`는 별도 테스트 DB에서
작은 음수의 업로드·미리보기·저장·다운로드 및 긴 핀 도착 시간 표시까지 검사합니다.
표현 범위 밖의 수치가 거부되고 편집기 입력이 유지되며 저장 버튼이 나타나지 않는지도 확인합니다.

## 비교할 보고서의 분석 조건 확인

런 비교 화면의 **분석 조건과 원본 근거**에서 리비전·시나리오·툴 버전·검증 범위·
원본 해시를 기준과 대상별로 확인합니다. 누락된 값은 **미등록 / 정보 부족**으로 표시합니다.
같은 해시의 보고서에 서로 다른 시나리오를 입력할 수 있으므로, 해시가 같다는 이유로
코너나 제약 설정이 같다고 판단하지 않습니다. 이 정보는 제출된 기록이며 별도 검증된 식별자가 아닙니다.
각 런 카드의 **실행 근거 보기**에서 원본 보고서를 열고 근거 JSON을 내려받을 수 있습니다.

`scripts/browser_comparison_context_check.mjs`는 새 인증 테스트 DB에서 보고서 두 개를 저장한 뒤
조건 차이·동일 원본 해시·원본 열기·기준/대상 전환·URL 복원·누락 조건·모바일 너비를 검사합니다.
기존 브라우저 검사와 같은 `SIGNOFF_AUTH_FIXTURE`, `SIGNOFF_TEST_UI` 변수를 사용합니다.

## 저장된 원본 파일 내보내기

`GET /runs/{run_id}/evidence/source`는 프로젝트 조회 권한을 확인한 뒤 저장된
`source_text`를 UTF-8로 인코딩하고 `source_sha256`과 대조합니다. 일치하면
OpenSTA는 `run-{id}-source.json`, RTL은 `run-{id}-source.sv`로 내려받습니다.
저장된 문자열의 BOM·줄바꿈·공백은 다시 포맷하거나 정규화하지 않습니다.
이는 저장 시점의 입력을 재현하는 기능이며, 업로드 전 파일 인코딩이나 RTL 저장 전에
정규화된 내용까지 복구하는 기능은 아닙니다.

응답은 `application/octet-stream`, `Cache-Control: no-store`,
`X-Content-Type-Options: nosniff`, `X-Source-SHA256`을 포함합니다.
해시 불일치·해시 누락·다운로드 가능한 소스 없음은 409이며 첨부 파일을 반환하지 않습니다.
레거시 근거 없음·런 없음·프로젝트 접근 불가는 404입니다.

프로젝트 및 타이밍 경로 화면의 **실행 근거 보기 → 원본 파일 다운로드**에서 사용합니다.
실패 사유와 재시도를 제공하며, 기존 근거 JSON 내보내기도 유지합니다.
SHA-256 일치는 보관된 내용의 일치만 확인합니다. 툴 실행의 진위, 전체 STA 범위,
외부 변경 불가능성 또는 독립적인 서명을 증명하지 않습니다.

검증: 원본 내보내기·실행 근거·보고서 가져오기·타이밍 경로 테스트 89개 통과,
프런트엔드 빌드 통과. `scripts/browser_source_export_check.mjs`로 임시 인증 DB에서
BOM/CRLF/한글을 포함한 다운로드 바이트와 해시, 오류 후 재시도, 320/390/1440px 화면을 확인했습니다.

## 핀 사이의 도착 시간 차이

경로 상세 API는 각 핀의 `arrival_delta_ps`와 경로 전체의 `arrival_delta_summary`를 반환합니다.
차이는 바로 앞 핀과 현재 핀에 모두 유효한 도착 시간이 있을 때만 계산합니다.
첫 핀, 누락·비수치·비유한 값이 있는 쌍은 `null`이며 누락 핀을 건너뛰어 계산하지 않습니다.
음수와 0을 보존합니다. 페이지 첫 핀도 원본의 직전 핀과 비교합니다.

요약은 전체 인접 쌍 수, 계산 가능한 쌍 수, 양의 증가가 큰 상위 5개 구간을 제공합니다.
동일한 차이는 보고서 핀 순서로 정렬합니다. 요약은 핀 페이지와 무관하며, 화면에서
해당 구간의 끝 핀이 있는 페이지로 이동할 수 있습니다. 시간 차이 표시는 최대 8자리
유효숫자를 사용하지만 API 값과 원본 보고서는 표시용 반올림으로 변경하지 않습니다.

이는 보고된 인접 도착 시간의 차이입니다. 개별 셀 지연과 배선 지연을 분리한 값이나
물리적 원인을 확정한 결과가 아닙니다. 계산 가능한 양의 증가가 없더라도 미보고 구간의
지연이 0이라는 뜻은 아닙니다.

검증: 타이밍 경로 테스트 38개 통과, 프런트엔드 빌드 및 브라우저 검증 통과.
페이지 경계, 누락·비정상 값, 음수·0·아주 작은 음수, 상위 구간 이동,
URL 재조회와 모바일 화면을 확인했습니다.

## 경로 그룹별 탐색

타이밍 경로 화면의 **보고서 경로 그룹**은 검색 조건과 무관한 전체 보고 경로를
그룹 이름과 min/max별로 집계합니다. 경로 수, 음수·0 이상·제약 없음 수, 최악 보고
슬랙을 표시하며 중복 경로는 유지합니다. 이 수치는 전체 설계의 WNS/TNS가 아닙니다.
그룹 보기는 기존 검색·슬랙 범위·페이지·선택을 지우고 해당 그룹과 유형으로 이동합니다.
그룹 목록은 10개씩 표시합니다. AI 호출이나 승인 상태 변경은 발생하지 않습니다.

`GET /runs/{id}/timing-paths`의 `groups`는 보고서 전체 집계입니다. 선택 조건에 따른
`summary`와 구분합니다. `path_group` 쿼리는 최대 200자이며 대소문자·공백·특수문자를
포함해 정확히 일치합니다. 생략하면 모든 그룹이고 빈 문자열은 빈 이름만 검색하므로,
현재 가져오기 규칙에서는 결과가 없습니다. 다른 필터와 AND로 결합됩니다. JSON/CSV
내보내기에도 같은 조건이 적용되고 `filters`/`filters_json`에 보존됩니다.
