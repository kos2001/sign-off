# 런에 저장되는 AI 검토

프로젝트 또는 타이밍 경로 화면에서 **실행 근거 보기 → AI 검토 요청 · 기록 저장**으로
보관된 RTL/OpenSTA 근거에 대한 검토를 요청한다. 기존 분석·게이트 자동 검토는 화면 전용이며,
이 기능은 사용자가 별도로 요청하는 영속 검토다. 자동 호출의 위반 조건을 적용하지 않아
보고된 위반이 없는 경우에도 검증 범위와 누락 근거를 검토할 수 있다.

## 기록과 권한

- `POST /runs/{run_id}/agent-reviews`: editor 이상, CSRF 필요(required 모드).
  본문은 UUID `request_key` 하나이며 임의 의견·근거·요청자 입력은 허용하지 않는다.
- `GET /runs/{run_id}/agent-reviews`: viewer 이상, 최신 20건. `next_before_id`를
  `before_id`로 전달해 앞선 기록을 조회한다. 목록은 큰 입력/의견 본문을 포함하지 않는다.
- `GET /runs/{run_id}/agent-reviews/{review_id}`: 해당 런의 기록과 입력 스냅샷 조회.
  다른 프로젝트 또는 다른 런에 속한 기록은 반환하지 않는다.

서버가 저장된 원본 해시를 확인하고 근거를 읽는다. RTL은 보관된 분석 결과를 전달한다.
OpenSTA는 보고서 메타데이터·범위·집계와 낮은 슬랙 순으로 최대 20개 경로를 전달한다.
제약 없는 경로는 뒤에 배치하며 선택 범위를 입력에도 명시한다. 입력은 256 KiB 이하다.
원본 불일치는 호출 전에 거부한다. 모델 출력이 1 MiB를 넘으면 완료 의견으로 저장하지 않는다.

`run_agent_reviews`에 요청 접수부터 기록한다. 요청자 ID/이름, 입력 스냅샷, 요청의 공통·역할
프롬프트, 설정된 모델 별칭, 결과와 완료 메타데이터를 보존한다. 입력과 완료 의견의 수정·삭제 기능은 없다. 오래된 미완료 접수에는 아래의 소유자 종결 기능을 제공한다. 자동 승인이나 원래 런 판정 변경도 하지 않는다.

## 재시도와 중단

동일 런과 동일 request_key는 기존 접수/결과를 반환하며 추가 모델 호출을 하지 않는다.
새 검토는 새 키를 사용한다. 접수는 공급자 호출 전에 커밋하고 호출 중 DB 쓰기 트랜잭션을
유지하지 않는다. 실패 결과도 기록한다. 연결 오류 후 화면의 「같은 요청 다시 확인」으로
서버에 이미 접수된 결과를 확인할 수 있다.

프로세스 강제 종료로 완료 기록을 쓰지 못하면 `running` 접수가 남을 수 있다.
이는 실제 실행 중이라는 보장이 아니다. UI는 「완료 확인 전」으로 표시하며 자동 재실행하지 않는다.
최근 2분 내 접수는 주기적으로 확인하고 오래된 접수는 수동 새로고침으로 확인한다.
이 기능은 재시작 후 작업을 자동 복구하는 작업 큐가 아니다.

## 보존 범위

기록은 SQLite 백업/복원 대상이다. 익명 로컬 요청의 사용자 ID는 null을 허용하고,
사용자 ID가 있으면 백업 검사에서 참조 유효성을 확인한다. 기존 DB에는 시작 시 테이블을 추가한다.

모델 별칭은 실제 모델 버전 증명이 아니다. 보존되는 지침은 API 요청 프롬프트이며
Hermes의 SOUL 등 공급자 시스템 설정 전체는 포함하지 않는다. 따라서 완전한 모델 실행
재현이나 외부 변경 불가능성을 보장하는 서명 감사 로그로 취급하지 않는다.

## 검증

- 전체 백엔드 테스트 597개 통과, 1개 건너뜀.
- 백업 fixture에 로컬/인증 사용자 검토를 모두 넣어 백업·복원 보존을 추가 검증했다.
- 관련 검토·백업 테스트 44개 통과. 동시 동일 키, 원본 불일치, 입력 제한,
  요청자 귀속, 역할 권한, 실패 기록과 커서 페이지를 포함한다.
- 프런트엔드 빌드 통과.
- `scripts/browser_saved_reviews_check.mjs`: 임시 인증 DB와 실제 Hermes 호출로 저장,
  새로고침 후 유지, 동일 키 재조회, viewer 읽기 전용, 320/390/1440px 배치를 확인했다.

### 후속 운영 보강 · 목록 조회와 완료 확인

목록 SQL은 요약 필드만 가져오며 입력 스냅샷·의견·지침·모델 별칭 본문은 읽지 않는다.
지연 로딩도 금지해 목록에 필드가 추가되면서 큰 본문 조회가 재발하면 검증에서 드러나도록 했다.

목록과 상세의 `completion_overdue`는 서버의 UTC 시각 기준으로 계산한다.
`status=running`이고 접수 후 2분 이상 경과한 경우에만 true이며, DB 상태 자체는 변경하지 않는다.
UI는 이를 「완료 확인 필요」로 표시하고 주기 조회를 멈춘다. 수동 새로고침은 계속 가능하다.
완료 기록 부재는 실행 중단의 증명이 아니며, 자동 재실행하지 않는다.
사용자 기기 시각이 다르더라도 이 분류는 서버가 결정한다.

후속 검증: 검토 API 테스트 27개와 빌드 통과. 경계 시각·상태별 분류·UTC 처리,
목록 SQL의 본문 제외를 확인했다. 실제 Hermes 저장/재조회 브라우저 검증과 함께
완료 확인 필요 상태의 조회 중단·수동 새로고침을 모의 응답으로 재현했다.

### 검토와 입력 근거 내보내기

저장된 검토 상세의 **검토·근거 JSON 다운로드**에서 파일을 받을 수 있다.
`GET /runs/{run_id}/agent-reviews/{review_id}/export`는 viewer 이상의 조회 권한으로
해당 런에 속한 기록만 반환한다. 형식은 `signoff/run-agent-review-export/v1`이며
UTC 내보내기 시각, 기록 전체(요청자·상태·입력 스냅샷·요청 지침·모델 별칭·의견),
해석 범위 안내를 포함한다. 미완료와 실패도 상태를 바꾸지 않고 내보낸다.

이는 모델에 전달했던 입력 스냅샷이다. 전체 원본 보고서 파일은 실행 근거의
원본 파일 다운로드로 별도로 받을 수 있다. 파일은 사인오프 승인, 실제 공급자 모델
버전 증명 또는 외부 불변 감사 로그를 의미하지 않는다.

파일명은 `run-{run_id}-review-{review_id}.json`이며 UTF-8 JSON 전체를 만든 뒤
2 MiB 제한을 확인한다. 초과하면 413을 반환하고 부분 첨부 파일을 만들지 않는다.
응답은 no-store/nosniff이며 브라우저는 응답 바이트를 재직렬화하지 않고 다운로드한다.
다른 런의 기록, 접근 불가 프로젝트 및 없는 기록은 404다.

검증: 검토 API 테스트 32개, 프런트엔드 빌드, 실제 Hermes를 사용한 임시 DB 브라우저
검증 통과. 내보낸 바이트와 서버 응답의 일치, 저장된 스냅샷·상태 유지,
권한·크기 경계, 오류 시 파일 미생성 및 재시도를 확인했다.

### 오래된 미완료 접수의 운영자 종결

`POST /runs/{run_id}/agent-reviews/{review_id}/close`는 프로젝트 owner 이상만
사용할 수 있다(required 모드 CSRF 적용). 본문은 공백 제외 1–1000자의 `reason`이며
요청자 신원은 서버 세션에서 가져온다. 로컬 모드는 기존과 같이 owner 권한으로 동작한다.
서버 기준 접수 후 2분 이상 지난 `running` 접수만 `failed`로 전환한다.
완료·실패·이미 종결된 요청 및 최근 접수는 409, 다른 런의 요청은 404다.

상세 화면에서 사유를 입력하고 **미완료 검토 종결**을 실행한다. 이력은 삭제되지 않으며
`outcome.error=review_closed_by_operator`와 `outcome.closure`에 종결자 이름/ID,
UTC 시각, 사유를 보존한다. 입력 스냅샷·지침·요청 키는 유지되고 JSON 내보내기에도 포함된다.
이 결정은 모델 실행 취소나 공급자 작업 중단의 증명이 아니다. 공급자가 계속 실행될 수 있다.

운영자 종결과 모델 결과 저장은 모두 `status=running` 조건의 원자적 갱신을 사용한다.
먼저 반영된 종료 상태를 유지하며 늦은 모델 응답은 종결 사유를 덮어쓰지 않는다.
모델 응답이 먼저 저장되면 종결은 409로 거절된다. 종결 후 같은 요청 키는 기존 실패 기록을
반환하며 다시 실행하지 않는다. 재검토는 새로운 요청이다. 작업 큐 및 자동 복구는 별도 과제다.

검증: 검토·인증 관련 58개 테스트와 추가 동시 종결 테스트 통과(종결 테스트 총 6개).
프런트엔드 빌드 및 `scripts/browser_review_closure_check.mjs` 임시 인증 DB 검증 통과.
owner/editor/viewer 권한, 오류 후 재시도, 재조회·내보내기, 320/390/1440px 배치를 확인했다.

동시 요청 제한과 한도 도달 후 재요청 방식은 [AI 검토 처리 용량](review-capacity.md)을 참고한다.
