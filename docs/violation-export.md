# 위반 검토 결과 내보내기

위반 검토 화면의 **검색 결과 JSON 내보내기**는 적용된 검색 조건에 맞는 전체 위반을 저장합니다.
현재 페이지와 페이지 크기는 적용하지 않습니다. 검색창에 편집 중인 값은 검색을 누른 뒤 적용됩니다.
화면을 연 뒤 다른 검토자가 상태를 변경했다면 다운로드 시점의 상태가 파일에 반영될 수 있습니다.

`GET /projects/{project_id}/violations/export`는 목록과 같은 `q`, `status`, `severity`,
`domain`, `stage`, `latest_only`, `sort` 조건을 받습니다. 프로젝트 viewer 이상이 사용할 수 있으며
프로젝트 밖의 사용자는 404를 받습니다. 결과를 내려받아도 위반·런·게이트 상태는 변경되지 않습니다.

- 파일명: `project-{project_id}-violations.json`, 형식: `signoff/violation-export/v1`.
- UTC 내보내기 시각, 프로젝트 ID, 적용 필터와 최신/과거 런 범위를 포함합니다.
- `total`과 `open_blocking`은 실제 내보낸 항목에서 계산한 전체 수와 미해결 Error/Critical 수입니다.
- 항목마다 위반 ID·체크·위치·설명·현재 상태·버전 및 런의 도메인·스테이지·툴·상태를 포함합니다.
- 현재 웨이버의 승인자·승인 계정 ID·사유·생성 시각을 포함하며, 웨이버가 없으면 null입니다.

최신 런은 먼저 단계·도메인별로 선택한 뒤 위반 조건을 적용합니다. 최신 런에 위반이 없더라도
이전 런의 위반을 대신 넣지 않습니다. 과거 항목까지 필요하면 **과거 런 포함**을 선택하세요.

내보내기는 한 번의 위반/런/웨이버 결합 조회에서 항목과 집계를 구성합니다.
최대 10,000건 또는 UTF-8 JSON 8 MiB(8,388,608바이트)이며 어느 한도를 넘더라도 HTTP 413으로 거절합니다.
크기는 한글·이스케이프 문자와 필터·집계 등 파일 전체를 포함합니다. 한도와 정확히 같은 크기는 허용합니다.
조회 결과를 행 단위로 인코딩하고 한도 초과를 발견하면 조회를 닫습니다. 전체 파일이 준비되기 전에
첨부 응답을 시작하지 않아 일부 결과를 전체 파일처럼 제공하지 않습니다.
필터를 좁혀 다시 시도하세요. 빈 결과는 0건과 빈 `items` 배열을 가진 파일로 저장됩니다.
모든 정상 다운로드 응답은 `Cache-Control: no-store`이고, 실패하면 화면에 오류와 재시도 버튼을 유지합니다.
브라우저는 서버의 JSON을 다시 들여쓰기하지 않고 그대로 저장합니다. 이 제한은 출력 크기 기준이며,
DB에 저장된 단일 설명의 크기나 서버 프로세스 전체 메모리 사용량의 상한을 의미하지는 않습니다.

이 파일은 현재 기록된 검토 상태입니다. 상태 전이 전체 이력이나 원본 툴 보고서는 포함하지 않습니다.
필요한 경우 각 위반의 검토 이력과 런의 실행 근거를 별도로 보관하세요. 위반이 없다는 것만으로
전체 설계의 검증 완료를 증명하지 않으며, 내보내기 시각 이후의 검토 변경도 파일에 자동 반영되지 않습니다.

## 개별 위반의 상태 변경 이력 보관

화면의 변경 이력은 최근 변경부터 25건씩 조회합니다. **이전 변경 더 보기**로 이어 읽고,
**이력 새로고침**으로 조회를 시작한 뒤 추가된 변경을 포함합니다. 페이지 조회가 실패해도
이미 읽은 이력은 유지하며 같은 버튼으로 다시 시도할 수 있습니다.

`GET /violations/{violation_id}/history/page`의 기본 `limit`은 25, 최대는 100입니다.
첫 응답의 `snapshot_max_id`와 `next_before_id`를 다음 요청의 `snapshot_max_id`, `before_id`로
전달합니다. 응답은 최신 이벤트 ID 순이며 `total`은 해당 조회 기준의 총건수입니다.
`next_before_id: null`이면 끝입니다. 이어 읽을 때 조회 기준을 빠뜨리거나 유효 범위 밖의
커서를 보내면 422입니다. 새 이벤트는 기존 기준 밖에 있으므로 페이지 중간에 끼어들지 않습니다.
두 커서를 생략하면 최신 기준으로 다시 시작합니다. 기존 배열 응답인 `/history`도 유지됩니다.

위반 상세에서 **변경 이력 → 변경 이력 JSON 내보내기**를 선택합니다.
`GET /violations/{violation_id}/history/export`는 현재 위반·런·웨이버 정보와 기록된 모든
상태 전이를 이벤트 ID 순서로 저장합니다. 각 이벤트의 이전/이후 상태, 처리자 이름,
로그인 계정 ID(직접 입력이면 null), 사유와 시각을 포함합니다. 웨이버를 해제해도
과거 승인 및 재오픈 이벤트는 파일에 포함됩니다.
내보내기는 화면에서 읽은 페이지 수와 무관하며 다운로드 시점의 기록 전체를 오래된 순서로 담습니다.

파일명은 `violation-{violation_id}-history.json`, 형식은 `signoff/violation-history-export/v1`입니다.
`violation`에 현재 상태와 버전, `events`에 이력, `total`에 이벤트 수를 저장합니다.
현재 상태와 이력은 하나의 결합 조회에서 읽고, 인증 시 미리 읽은 객체도 그 조회 결과로 갱신합니다.
프로젝트 열람 권한을 적용하며 내보내기로 상태나 이력을 변경하지 않습니다.

최대 10,000개 이벤트·UTF-8 JSON 8 MiB이며 초과 시 파일 없이 413을 반환합니다.
필터 없이 기록 전체를 내보내는 기능이므로 상한을 넘는 대규모 감사 자료는 별도 추출이 필요합니다.
과거 이력이 기록되지 않은 기존 데이터는 `events: []`일 수 있습니다. 이벤트 수를 위반 버전과
단순 비교해 이력이 완전하다고 판단해서는 안 됩니다. 원본 툴 보고서나 외부 불변 감사 로그의 대체물은 아닙니다.

## 검증

`backend/tests/test_violation_search.py`는 목록과 필터/순서 일치, 최신 런 선택, 전체 페이지,
웨이버/버전 보존, 빈 결과, 상한 초과 거절 및 접근 권한을 검사합니다.
UTF-8/JSON 이스케이프를 반영한 크기, 정확한 경계값, 조기 중단과 조회 종료도 검사합니다.
`scripts/browser_violation_export_check.mjs`는 임시 인증 서버에서 viewer 다운로드,
페이지 밖 결과, 미적용 검색어 제외, 과거 런 포함, 오류 후 재시도와 모바일 화면을 검사합니다.
다운로드 파일이 실제 API 응답 바이트와 같은지도 확인합니다.
임시 데이터에 300만 자의 한글 설명을 넣어 실제 8 MiB 초과의 413·파일 미생성과 필터 축소 후 복구도 검사합니다.

`backend/tests/test_violation_history_export.py`는 이력 순서·해제된 웨이버 사유·현재 상태·버전,
인증 시 먼저 읽은 객체 갱신, 빈 이력·접근 권한과 이벤트/크기 상한을 검사합니다.
브라우저 검사에도 실제 계정의 5개 상태 전이, 이력 파일 바이트 일치와 실패 후 재시도를 포함합니다.
페이지 회귀는 53건 순회, 새 이벤트 삽입 중 기준 유지, 빈 이력·커서 검증과 권한을 확인합니다.
브라우저에서는 25건에서 30건으로 이어 읽기, 오류 중 기존 목록 보존, 새로고침 후 추가된 2건 표시를 확인합니다.
